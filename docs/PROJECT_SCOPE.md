# Customer Agent 2 项目范围

## 1. 文档目的

本文档是项目范围的唯一事实来源。README、Issue、聊天记录或临时想法与本文档冲突时，以本文档和已接受 ADR 为准。

## 2. 项目定位

Customer Agent 2 是一个面向开源展示和求职简历的 Python 大模型应用项目，主要证明以下能力：

- 能设计并实现完整 RAG 应用链路。
- 能处理模型不稳定、检索失败、流式取消和配置错误。
- 能用固定数据集验证技术结论。
- 能解释架构选择、替代方案和工程取舍。

它不是普通电商后台，不以页面数量、CRUD 数量或代码行数为目标。

## 3. P0：首个可验证版本

### 3.1 文档入库

- 支持 Markdown、TXT、PDF、DOCX 和 CSV。
- 识别文件类型并选择解析器。
- 输出带来源信息的结构化文本块。
- 支持固定 Token 预算、Overlap 和基础清洗。
- 使用本地 Embedding 生成向量。
- 写入 PostgreSQL/pgvector。
- 文档重新入库时能够替换旧 Chunk，避免重复数据。

### 3.2 在线问答

- 提供非流式健康检查和流式问答 API。
- 加载最近会话历史并按配置生成摘要。
- 支持 Query Rewrite 和多问题拆分。
- 支持树形意图识别和低置信歧义提示。
- 根据意图限制知识库检索范围，低置信时允许全局兜底。
- 执行向量召回、去重、RRF、Rerank 和最终 TopK。
- 组装结构化 Prompt、引用编号和来源列表。
- 使用 SSE 输出状态、正文、来源、完成或错误事件。
- 支持全局超时、客户端断开和模型请求取消。

### 3.3 模型工程

- 最终回答模型和内部快速模型分别配置。
- Chat、Embedding 和 Rerank 通过接口解耦。
- 模型 ID、Base URL、超时和能力由环境配置提供。
- 额度不足或模型不可用时返回明确错误；支持配置化替换模型 ID。
- Rerank 未配置时只能显式进入 No-op 降级，日志和 Trace 必须可见。

### 3.4 数据与可观测性

- 数据库变更由 Alembic 管理。
- 保存知识库、文档、Chunk、会话、消息和最小 Trace 数据。
- 日志记录请求 ID、阶段、耗时、候选数量和降级原因。
- 不在日志中记录 API Key 和完整敏感文档。

### 3.5 测试与评测

- 单元测试覆盖分块、去重、RRF、意图解析、配置校验和错误降级。
- 集成测试覆盖 PostgreSQL/pgvector、Redis 和主要 API。
- 使用 20 条固定样本执行 Smoke Evaluation。
- 使用 150 条固定样本执行完整 Evaluation。
- 至少报告 Intent Top-1、Retrieval Hit@K、MRR、延迟和失败样本。
- 必须完成 Rerank ON/OFF 单变量对比，不预设或编造效果数字。

## 4. P1：开源展示增强

- 增加关键词检索通道并参与加权 RRF。
- 增加 MCP Client 与独立示例 MCP Server。
- 优先实现只读、可演示的订单查询、物流查询和售后资格检查工具。
- 增加 VLM 图片描述和扫描文档辅助解析。
- 支持 XLSX 和图片文件。
- 增加模型候选路由、首包探测和有限熔断降级。
- 输出可公开的评测报告和失败案例分析。

## 5. P2：暂不承诺

- LightRAG/Neo4j 知识图谱通道。
- 联网搜索通道。
- 完整 ReAct Agent 和长时间持久化执行。
- 多租户、部门级知识权限和复杂 RBAC。
- React 管理后台和可视化 Pipeline 编辑器。
- Kubernetes、高可用部署和生产级 SLA。
- 大规模压测、模型微调和 GPU 集群调度。

P2 能力只有在 P0、P1 验收完成且新增 ADR 后才进入开发计划。

## 6. 明确排除

- 不逐文件翻译 Ragent Java 代码。
- 不复制普通 Controller、DTO、Mapper 和管理后台 CRUD。
- 不为了“技术栈丰富”同时引入多个功能重叠框架。
- 不使用 Chat 模型替代专用 Embedding 或 Rerank 作为默认方案。
- 不把参考项目、课程文章或历史报告数字写成本项目实验成果。
- 不提交用户测试文档、模型权重、真实数据库和密钥。

## 7. P0 验收标准

P0 只有满足以下条件才可发布：

1. 从文档上传到流式回答的端到端链路可复现。
2. 每个核心阶段均有源码接口、结构化日志和测试锚点。
3. 模型超时、空检索、Rerank 失败和客户端断开有明确行为。
4. 20 条 Smoke Evaluation 可以一条命令执行。
5. 150 条完整评测可以生成结构化结果和失败样本。
6. README 的启动步骤在全新环境中验证通过。
7. Git 仓库不包含真实密钥、个人文档、缓存和模型文件。
8. 已知局限和未实现能力在 README 或发布说明中明确标注。

## 8. 当前外部条件

- 云端 Chat：阿里云百炼 OpenAI-compatible API。
- 本地 Embedding Baseline：`BAAI/bge-base-zh-v1.5`，768 维、512 Token、CPU。
- 默认向量存储：PostgreSQL + pgvector。
- Redis：用于缓存、会话辅助、限流和任务状态。
- Rerank：优先 `qwen3-rerank`，需要独立配置业务空间。
- VLM：预留 `qwen3.7-plus`，P1 启用。

这些条件是当前默认值，不是不可更改的永久结论。更换核心组件必须记录 ADR，并说明数据迁移与评测影响。
