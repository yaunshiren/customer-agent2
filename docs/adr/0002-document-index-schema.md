# ADR-0002：文档版本与向量索引模式

- 状态：Accepted
- 日期：2026-08-24
- 实现更新：2026-08-26（M2-G 在线向量召回）

## 背景

M2 需要保存知识库、文档、可重建版本和带来源的 Chunk。入库不能直接覆盖当前可检索
数据，否则解析、分块或 Embedding 中途失败会留下半成品。向量索引还必须明确记录
Embedding 模型、上游版本、维度和归一化策略，避免配置变化后静默混用向量。

当前 Baseline 已接受 `BAAI/bge-base-zh-v1.5`、768 维、L2 归一化和 Cosine 相似度。
PostgreSQL 17 与 pgvector 0.8.6 已作为现有基础设施运行。

## 决策

### 1. 四层持久化结构

首批业务表固定为：

1. `knowledge_bases`：知识库身份与不可静默切换的 Embedding 配置。
2. `documents`：同一知识库内由 `source_key` 唯一标识的逻辑文档。
3. `document_versions`：一次完整入库尝试及其状态、内容哈希和来源元数据。
4. `chunks`：属于一个文档版本的有序文本块、来源位置和向量。

主键使用 UUID，时间使用带时区时间戳，非查询关键的来源扩展信息使用 JSONB。内容和
来源标识保留 SHA-256 字段，为后续幂等判断提供稳定输入，但是否跳过重复版本由应用
用例决定，不用唯一约束阻止同内容按新解析器重新构建。

### 2. 原子版本切换

文档版本状态仅允许：

- `building`：解析、分块或写入尚未完成，不可检索。
- `active`：当前可检索版本。
- `failed`：构建失败，保留脱敏失败码，不可检索。
- `superseded`：曾经有效但已被新版本替换，不可检索。

数据库使用部分唯一索引保证每个文档最多只有一个 `active` 版本。后续入库用例先写完
新版本及全部 Chunk，再在同一事务中把旧版本改为 `superseded`、新版本改为 `active`。
在线检索必须连接 `document_versions` 并只读取 `active`。

### 3. 向量与检索作用域

`chunks.embedding` 使用 `vector(768)`，建立 `vector_cosine_ops` 的 HNSW 索引。
`chunks` 冗余保存 `knowledge_base_id`，使知识库过滤能在数据库查询中完成；复合外键
保证它与文档版本所属知识库一致。Chunk 顺序在同一版本内唯一。

知识库记录：

- `embedding_model_id`
- `embedding_model_revision`
- `embedding_dimension`
- `embedding_normalized`

当前数据库约束要求维度为 768 且已归一化。更换模型 revision 可以新建知识库或完整
重建索引；更换维度必须新增 ADR、迁移向量列并重建全部向量索引。

M2-G 按本决策实现在线召回：请求必须携带非空知识库 ID 集合，并在查询前逐个验证上述
四项索引身份；文档 ID、文档格式、解析器、章节和页码过滤全部进入数据库查询。查询连接
`document_versions` 且只读取 `active`，避免旧版或半成品 Chunk 进入候选。

> 该段请求作用域决策已由 [ADR-0015](0015-ragent-retrieval-scope.md) 取代；索引身份和 active-only
> 约束继续有效。

HNSW 对带过滤的近似查询可能在过滤后返回不足。当前实现在单次事务内使用
`hnsw.iterative_scan=strict_order`，并通过 `RETRIEVAL_HNSW_EF_SEARCH`（默认 100）控制
查询扫描宽度；这些设置使用事务本地作用域，不改变连接池后续请求。召回上限由
`RETRIEVAL_RECALL_BUDGET` 控制。

### 4. 删除语义

本阶段采用外键级联删除：删除知识库会删除其文档、版本和 Chunk；删除文档会删除版本
和 Chunk。M2-E 已在明确知识库作用域内提供文档硬删除 API；当前没有身份认证和恢复机制，
所以该接口仍只用于受控开发/演示环境。

## 备选方案

### 直接覆盖文档和 Chunk

表更少，但入库失败会让当前索引部分丢失或混入新旧数据，无法满足原子替换要求。

### 使用无固定维度的 `vector`

可以混合模型维度，但无法为不同维度稳定建立同一个近似索引，也会掩盖配置错误。

### 为每个知识库建立独立 Chunk 表

过滤和索引边界更直接，但迁移、表数量和运维复杂度会随知识库增长，不适合 P0。

### 只在关联表中保存知识库 ID

范式更纯，但向量检索必须先依赖额外连接才能限定知识库。当前选择受复合外键保护的
冗余字段，换取明确的数据库侧过滤入口。

## 后果

- 可以独立验证表约束、版本唯一性、向量维度和 Cosine 索引。
- 构建中和失败版本不会成为可检索数据，但清理策略需要在后续入库用例中实现。
- JSONB 只承载来源扩展信息；经常过滤、排序或建立约束的字段仍必须提升为正式列。
- HNSW 会增加写入成本和索引体积，后续用固定评测集确认召回与延迟，不在本 ADR 中
  声明效果数字。
- 本 ADR 不定义 Prompt、Rerank、SSE、问答 API 或检索效果数字；这些由后续阶段单独验证。
