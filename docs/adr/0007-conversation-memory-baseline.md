# ADR-0007：会话记忆与 M4 意图基线参数

- 状态：Accepted
- 日期：2026-08-27

## 背景

M3-C 已持久化 completed 会话消息，但基础 RAG Prompt 尚未读取历史。M4 还需要问题改写、
意图路由和歧义澄清；这些能力必须先固定记忆窗口、摘要触发点和分类阈值，才能建立可重复的
测试与后续单变量评测。

这些数值是用户确认的工程 Baseline，不代表已经通过评测证明最优。M4/M5 的固定样本会用于
验证并决定是否调整。

## 决策

### 1. 已确认参数及原因

| 参数 | Baseline | 原因 |
|---|---:|---|
| 最近消息窗口 | 6 轮 | 客服对话中的指代通常集中在最近几轮；保留 12 条完整 user/assistant 消息可覆盖短期上下文，同时限制 Prompt 长度、延迟和费用。 |
| 摘要触发点 | 超过 12 轮 | 短对话不额外调用模型；长对话达到 13 轮后才压缩旧消息，在上下文连续性和摘要调用成本之间保留缓冲。 |
| 初始路由 | 系统直答、知识库问答、需要澄清 | 这是当前 P0 可验证的最小行为集合，不提前虚构订单、物流等尚未接入的业务工具或知识域。 |
| 高置信阈值 | 0.75 | 采用偏保守的自动路由门槛，优先降低错误路由；低于阈值时允许显式兜底或澄清。 |
| Top1/Top2 歧义差值 | 0.10 | 两个候选分数接近时不强行选择；0.10 足够形成可解释的 Smoke Baseline，后续再由 Intent 样本校准。 |

阈值只在后续 M4 意图子阶段接入。M4-A 不伪造分类结果，也不把未实现阶段写入 Trace。

### 2. M4-A 最近记忆

每次持久化装饰器保存当前 user 消息后，记忆装饰器从 PostgreSQL 加载：

- 当前会话已有的持久化摘要（如果存在）。
- 最近 6 个 `completed` Run 对应的完整 user/assistant 消息对。

只加载 completed 消息对。当前 running Run 的 user 消息、no_context、failed、cancelled Run 和
残缺消息不会进入模型上下文。这样可以避免把当前问题重复注入，也不会把失败回答当作对话事实。

历史消息和摘要放入有明确边界的 `<conversation_memory>` 数据区并执行转义。它们只用于理解
指代和上下文，不作为知识事实来源；回答事实仍必须由 `<knowledge_context>` 支撑并引用。

### 3. 持久化摘要

新增 `conversation_summaries` 表，每个会话最多一行，保存摘要正文、覆盖到的最后消息 ordinal、
累计来源消息数、摘要模型 ID 和时间戳。

completed 回答及 assistant 消息提交后，摘要装饰器检查会话累计 completed 轮次：

- 不超过 12 轮：不调用快速模型。
- 超过 12 轮：保留最新 6 轮原文，把尚未摘要且已经滑出窗口的完整轮次与旧摘要增量合并。

超过阈值后的每个新 completed 轮次都会让最旧的一轮滑出 6 轮窗口，因此会触发一次增量摘要。
这避免旧摘要与最近消息之间出现上下文空档；代价是长会话后续每轮增加一次 fast 模型调用。

摘要使用配置的 fast Chat 模型、temperature 0、最多 512 输出 Token，并受独立 30 秒超时约束。
保存时使用乐观边界校验，迟到的摘要结果不能覆盖更新的摘要。

### 4. 降级与生命周期

- 记忆数据库读取失败属于主请求失败，因为静默丢失历史会改变用户问题语义。
- 摘要生成、超时、模型协议或保存失败只记录结构化告警，不改变已经成功的回答和 done 结局。
- 摘要失败后保留旧摘要；下一轮仍可使用最近 6 轮原文，因此满足可控降级。
- final 与 fast Chat 模型使用独立适配器和 HTTP 连接池，并由应用生命周期逆序关闭。

### 5. 当前不做的事

- 不实现 Query Rewrite、多问题拆分或意图分类；它们在后续 M4 子阶段独立接入。
- 不增加会话查询/编辑 API，不修改 SSE 公共事件。
- 不把摘要放入 Redis，不保存 Prompt、reasoning 或完整召回正文。
- 不声称 6/12/0.75/0.10 是最终最优参数。
- 轮数窗口只能控制消息数量，不能精确保证 Token 预算；全 Prompt 的 tokenizer-aware 预算与截断
  留给 M4 的 Prompt 模板管理子阶段，并必须单独测试。

## 备选方案

### 把全部历史消息直接发给模型

实现简单，但 Prompt 会无限增长，延迟和成本不可控，也更容易放大历史 Prompt Injection。

### 每轮都生成摘要

摘要更新及时，但短会话也会增加一次模型调用，失败面和费用都明显扩大。

### 摘要失败时让回答失败

数据最一致，但摘要是上下文压缩优化，不应推翻已经完成并持久化的用户回答。

## 后果

- 多轮 Prompt 可以稳定获得最近 6 轮 completed 历史和可选持久化摘要。
- 长会话不会无限扩大原文窗口，摘要失败仍能降级到最近消息。
- 默认运行时会同时创建 final 和 fast 两个 Chat 资源；本地测试继续使用 Fake，不调用真实云端。
- M4 后续可在同一记忆结构上实现 Rewrite 和 Intent，并用固定样本评测已确认阈值。
