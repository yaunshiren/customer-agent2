# ADR-0004：PDF、DOCX 与 CSV 安全解析边界

- 状态：Accepted
- 日期：2026-08-25

## 背景

M2-E 已通过统一上传端点完成 Markdown/TXT 的同步入库。P0 范围还要求 PDF、DOCX 和 CSV，
但二进制格式不能只相信扩展名或客户端 MIME，也不能把任意压缩包直接交给 Office 解析器。
解析结果仍需进入现有结构分块和事务化版本切换，不能为不同格式建立隐藏的旁路。

当前阶段没有 OCR、VLM、杀毒服务、隔离进程或对象存储。安全边界必须与这些事实一致，
并对可能导致高内存、超长计算或歧义数据的输入做确定性拒绝。

## 决策

### 1. 统一格式识别

公开上传端点路径和响应 Schema 不变，允许格式扩展为 Markdown、TXT、PDF、DOCX 和 CSV。
识别器继续校验扩展名与 MIME 一致性，并增加：

- PDF 必须以 `%PDF-` 文件头开始。
- DOCX 必须是有效 ZIP，并在解析前包含 `[Content_Types].xml` 与 `word/document.xml`。
- CSV、Markdown 和 TXT 只接受 UTF-8/UTF-8 BOM，并继续拒绝 NUL 和不安全控制字符。
- `.docm`、旧版 `.doc`、XLS/XLSX、扫描图片及其他格式保持拒绝。

扩展名缺失时可以使用明确 MIME 识别，但二进制签名仍必须通过。通用
`application/octet-stream` 只有在受支持扩展名存在时才接受。

### 2. 解析器与结构来源

- PDF 使用 pypdf 严格读取，不尝试密码、不执行 OCR；每页作为独立 `section_path`，页内文本
  按段落输出。加密文件和纯扫描件分别返回明确错误。
- DOCX 使用 python-docx，按正文顺序保留 Heading、普通段落、列表样式和表格记录；表格首行
  作为表头重复到每条记录，使每个 Chunk 可以独立理解。
- CSV 使用 Python 标准库的严格逗号分隔解析；第一条非空记录作为表头，每条数据记录重复
  表头，并拒绝列数不一致的歧义文件。

所有解析器仍输出同一 `ParsedDocument`/`ParsedBlock` 领域模型，复用 400/64 Token 分块、
Embedding、pgvector 写入和原子版本切换。

### 3. 资源限制

除现有单文件 50 MiB 默认上限外，类型化配置增加以下默认边界：

- 提取文本总量：5,000,000 字符。
- PDF：最多 1,000 页。
- DOCX：最多 2,000 个 ZIP 条目、解压后最多 200 MiB、压缩膨胀比例最多 100 倍。
- CSV：最多 10,000 条数据记录、200 列。

DOCX 还拒绝加密条目、路径穿越条目和 `vbaProject.bin` 宏内容。解析失败统一转换为稳定、
脱敏的 `DocumentError`，不向 HTTP 响应暴露底层库异常或文档正文。

### 4. 依赖与许可证

pypdf 和 python-docx 作为直接运行时依赖进入 `pyproject.toml` 与 `uv.lock`，并在 `NOTICE`
记录许可证。CSV 不增加第三方依赖。

## 备选方案

### Apache Tika 或独立解析服务

格式覆盖更广，但会增加 JVM/外部服务、网络边界和运维复杂度，超出当前 P0 本地纵向闭环。

### unstructured、LangChain Loader 或 LlamaIndex Reader

可以减少适配代码，但会隐藏格式识别、资源限制和结构映射，不利于当前项目展示可测试的显式边界。

### PDF OCR 与 DOCX 图片理解

能覆盖扫描件和图片，但需要 OCR/VLM、成本与超时策略。该能力属于 P1，当前明确返回不支持，
不能静默生成空索引。

### 容忍 CSV 不等长记录

自动补齐或截断更宽松，但会制造不可解释的列语义。当前选择拒绝并要求调用方先清洗。

## 后果

- 五种 P0 文档格式共享同一上传、状态、失败回滚和删除契约。
- 二进制原文件只在请求/入库内存生命周期内存在，仍不持久化到仓库或对象存储。
- PDF 页码通过 `section_path` 保留；DOCX 的来源行号表示正文结构序号，不是版面坐标。
- CSV 仅支持 UTF-8 逗号分隔，不自动猜测分隔符或编码。
- 扫描 PDF、宏文档、旧版 Office、XLSX 和超出资源限制的文件会被明确拒绝。
