# ADR-0013：M5-D Intent 失败切片与候选树实验

- 状态：Accepted（实验协议已完成；v3 候选未通过晋级门禁）
- 日期：2026-08-31
- 完成日期：2026-09-01
- 关联：[ADR-0009](0009-intent-routing-and-guidance.md) 和
  [ADR-0012](0012-full-evaluation-dataset-and-protocol.md)

## 背景

M5-C 使用 `qwen3.8-flash`、`m4-c-v1` 意图树和 0.75/0.10 阈值完成 150 条真实 Intent，得到
128/150（85.33%）总体准确率。RAG 为 121/132（91.67%），no-rag 为 7/18（38.89%）。在修改
线上路由前，需要先判断错误来自阈值、意图定义还是数据集标签边界，且不能为比较候选方案重复
修改多个变量。

离线切片严格连接固定数据集标签与脱敏 M5-C 报告，只输出聚合计数和 Query ID：

- 22 条错误按一级意图分为 SUPPORT 9、FEEDBACK 10、CHAT 3。
- 17 条错误进入 `clarification`：13 条 `explicit_clarification`、4 条 `low_confidence`。
- 5 条 no-rag 被高置信送入 `knowledge_base`；没有出现应检索却进入 `system_direct`。
- v1 报告没有保存三路候选分数，因此不能可靠地离线扫描 0.75/0.10 阈值。

失败样本表明 v1 边界没有明确覆盖“只接收功能建议或投诉”和“对天气、竞品评价等问题说明能力
边界”；同时对“虽然缺少具体条件，但仍可先检索通用规则并附限制”的问题过早澄清。这个结论
只用于提出候选实验，不等于 v2 已经有效。

## 决策

### 1. 线上默认保持不变

`src/customer_agent2/config/intent_tree.json` 继续使用 `m4-c-v1`。候选树放在 `evaluation/config/`
并使用独立版本；只有完整真实实验通过预先登记的门槛后，才讨论是否提升为线上默认。不同候选
必须使用独立报告和缓存路径，运行器通过树语义哈希拒绝跨候选复用，也拒绝覆盖 M5-C 基线。

### 2. 候选只改变意图描述

`m5-d-v2-candidate` 保持三个路由、模型、结构化输出协议和确定性选择算法不变，只细化：

- `system_direct`：接收纯功能建议、纯意见或投诉；对当前知识库/工具之外的问题说明能力边界，
  不编造外部事实。
- `knowledge_base`：文档能提供通用规则、流程、产品说明或条件化判断时先检索；带情绪但同时有
  可检索产品/服务问题时也检索。
- `clarification`：只有缺少信息导致连安全的通用说明或边界回复都无法给出时才澄清；不能仅因
  问题简短、带投诉情绪或需要附条件说明而澄清。

v2 第一阶段暴露四个仍不明确的通用边界。`m5-d-v3-candidate` 继续只改三段描述：选购建议即使
较宽泛也可先检索目录；补货/到货等明确业务类型即使暂缺商品名也先进入业务路径；以疑问句表达的
界面功能缺失仍可属于反馈；主要询问第三方竞品时不能因为可顺带介绍自营商品就改走知识库。

### 3. 分阶段单变量真实实验

候选实验固定 `ragenteval-v1-all` 150 条、`qwen3.8-flash`、温度 0、关闭思考、最大输出 256、
评测专用超时 60 秒、高置信阈值 0.75、歧义差值 0.10。与 M5-C 相比唯一实验变量是 Intent Tree
描述。运行保持串行、零重试、首个降级安全终止，但按以下累计阶段逐步授权：

1. 失败集：先运行 M5-C 的 22 条历史错误。11 条应检索和 11 条 no-rag 各至少修复 8 条，且
   under-retrieval 必须为 0；否则停止，不支付后续调用。
2. 回归集：第一阶段通过后增加 18 条 M5-C 原本正确的保护样本。它包含 SUPPORT/FEEDBACK/CHAT
   6/5/7 条、应检索/no-rag 11/7 条，至少保持 17/18 正确且 under-retrieval 为 0；否则停止。
3. 完整集：前 40 条通过后再补剩余 110 条，最终仍按完整 150 条和第 4 节门槛作晋级判断。

22 条失败集用于快速判断候选是否确实针对已知问题，18 条回归集用于防止只修失败样本却破坏原本
正确的边界。两者都是带偏的筛选集，不能替代完整集结论。`evaluation/config/m5d-intent-stages.json`
只保存固定 Query ID；运行器会把它与 M5-C 基线重新核对，拒绝分层或标签漂移。

第一阶段 `8/11 + 8/11` 要求候选至少修复 16/22，并防止收益只集中在应检索或 no-rag 一侧；第二
阶段 `17/18` 最多容许 1 条模型波动，但不能形成系统性回归。两个阶段都把 under-retrieval 固定为
0，因为把本应检索的问题直接回答会绕开知识依据。这些整数门槛只用于控制是否值得继续付费，
最终有效性仍由完整集的预登记门槛决定。

新报告保存三个 0～1 候选分数，但仍不保存 Query、Ground Truth、澄清文本、模型原始响应、API
Key 或 Workspace ID。阶段缓存同时绑定数据集、阶段清单、M5-C 基线、模型、树版本与规范化语义
SHA-256、阈值、超时和生成参数，防止同版本文件被编辑后错误续跑。每条成功结果在下一次请求前
原子落盘；同一候选跨阶段按 Query ID 复用，无失败时完整通过累计恰好 150 次，而不是
22+40+150。降级或网络失败的调用不标记成功，续跑时会再次要求对剩余样本精确授权，因此实际
计费尝试数可能高于 150。同一缓存同时只允许一个运行进程，避免两个终端对同一缺口重复调用。
阈值重放复用同一轮分数，不产生额外模型调用。

### 4. 预先登记晋级门槛

候选只有同时满足以下条件，才可进入“是否替换线上默认树”的决策：

1. 150 条样本全部取得成功结果，运行器不做自动重试；若曾有失败尝试，阶段报告必须单独披露次数。
2. 总体正确数严格高于 M5-C 的 128/150。
3. RAG 正确数不低于 121/132。
4. no-rag 正确数严格高于 7/18。
5. 应检索却进入 `system_direct` 的 under-retrieval 仍为 0。

这些门槛使用原始 0.75/0.10 阈值。基于同一 150 条分数挑出的其他阈值只算探索性结果，不能在
同一数据集上同时完成调参和无偏验收；若要推广阈值，需另建留出集或独立验证协议。

## 验证记录

v2 第一阶段真实运行严格使用上述固定参数：22/22 成功、0 失败、零自动重试，总正确 18/22；
11 条应检索正确 9 条，11 条 no-rag 正确 9 条。`failure_rag_correct` 和
`failure_no_rag_correct` 均通过，但出现 1 条 under-retrieval，因此第三项安全门禁失败。错误还
包括 1 条 clarification 和 2 条 over-retrieval。运行器按协议停止，没有执行 18 条回归集或剩余
110 条。脱敏报告为 `evaluation/reports/m5d-intent-v2-failures.json`。

v3 使用 v2 的四条错误作开发反馈，因此这 22 条不再是独立验证集。v3 第一阶段随后完成 22/22
成功、0 失败、零自动重试，总正确 22/22；应检索/no-rag 均为 11/11，under-retrieval、
over-retrieval 和 clarification 均为 0，共记录 12,410 输入 Token 和 1,017 输出 Token。三项第一
阶段门禁全部通过，脱敏报告为 `evaluation/reports/m5d-intent-v3-failures.json`。v2 缓存没有复用
到 v3。

第二阶段复用这 22 条，只新增 18 条 M5-C 原本正确的保护样本。18/18 调用成功、全部正确、0 失败、
零自动重试；累计 40/40，SUPPORT/FEEDBACK/CHAT 为 15/15、15/15、10/10，应检索/no-rag 为
22/22、18/18，under-retrieval、over-retrieval 和 clarification 均为 0。累计记录 22,540 输入
Token 和 1,870 输出 Token，五项第二阶段门禁全部通过。脱敏累计报告为
`evaluation/reports/m5d-intent-v3-guard.json`。前 40 条证明候选值得继续付费验证，但不替代完整集。

第三阶段复用前 40 条缓存，只新增剩余 110 次真实调用。最终 150/150 请求成功、0 失败、零自动
重试；总体正确 149/150，RAG 为 131/132，no-rag 为 18/18，SUPPORT/FEEDBACK/CHAT 为
124/125、15/15、10/10。累计记录 84,851 输入 Token 和 6,747 输出 Token，延迟 P50/P95 为
693.270/961.267 ms。唯一错误 `S3-08` 应进入 `knowledge_base`，却以 0.95/0.05/0.00 的三路
分数进入 `system_direct`；因此 under-retrieval 为 1，over-retrieval 和 clarification 均为 0。
总体、RAG、no-rag 三项准确率门槛全部通过，但 `full_under_retrieval == 0` 安全门禁失败，v3
候选不进入线上替换讨论。脱敏阶段报告与标准完整报告为
`evaluation/reports/m5d-intent-v3-full.json` 和 `evaluation/reports/m5d-full-intent-v3.json`。

## 后果

- 失败分析、候选配置、分阶段付费保护和完整真实实验均已完成；150 条成功缓存不得重复付费运行。
- v3 准确率明显高于 M5-C，但因 1 条漏检索未通过预登记安全门禁，候选不晋级。
- 线上默认树继续使用 `m4-c-v1`，本次候选实验没有影响在线用户请求。
- 每个阶段只接受与当前缓存缺口完全相等的费用授权；失败或中断后续跑只确认尚未成功的条数。
- 通过全部阶段仍会累计产生 150 次真实费用，完整结论的统计口径没有缩小。
- v3 的唯一错误已转入 [ADR-0014](0014-intent-v4-focused-validation.md) 的新候选与聚焦验证，
  不能复用 v3 缓存或把同一 150 条再次包装成独立结论。
