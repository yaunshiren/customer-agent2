# ADR-0003：最小文档入库 API 契约

- 状态：Accepted
- 日期：2026-08-25

## 背景

M2-D 已完成内存文档到 pgvector 的事务化入库，但调用方还不能通过公开 HTTP 契约创建
知识库、上传文档、查询版本状态或删除逻辑文档。M2 需要先形成一个可复现的最小纵向入口，
再扩展 PDF/DOCX/CSV 和后台任务能力。

当前没有任务队列、对象存储、权限系统或多租户边界。公开 API 必须如实表达这些限制，
不能把同步请求包装成尚不存在的后台任务，也不能在错误中泄露数据库、模型缓存或原始文档。

## 决策

### 1. API 版本与端点

M2-E 在现有 `/api/v1` 前缀下增加：

1. `POST /knowledge-bases`：创建使用当前固定 Embedding 配置的知识库。
2. `POST /knowledge-bases/{knowledge_base_id}/documents`：使用 multipart 上传一个文档；
   `file` 必填，`source_key` 可选，省略时使用安全化后的文件名。
3. `GET /knowledge-bases/{knowledge_base_id}/documents/{document_id}`：返回逻辑文档与最新
   入库版本状态。
4. `DELETE /knowledge-bases/{knowledge_base_id}/documents/{document_id}`：在知识库作用域内
   删除逻辑文档，并使用已接受的外键级联删除其版本和 Chunk。

本阶段不增加知识库列表、文档列表、版本历史分页或知识库删除等通用管理 CRUD。

### 2. 同步上传语义

上传请求直接等待 Identify、Parse、Chunk、Embed 和 Index 完成。只有新版本已经原子切换为
`active` 后才返回 HTTP 201。解析、模型或数据库失败返回结构化错误，不返回虚假的任务 ID。

该选择适合 P0 的本地 CPU 最小闭环，但长文档会占用较长 HTTP 请求时间。后台任务、进度
轮询、重试调度和 Redis 任务状态需要任务队列与恢复语义，后续必须单独决策，不能在本阶段
用 FastAPI `BackgroundTasks` 伪装成可靠任务系统。

### 3. 上传边界与资源释放

- API 在应用层限制之外再执行有界读取，最多读取 `UPLOAD_MAX_FILE_MB + 1 byte`，超限即拒绝。
- 无论成功、验证失败、取消或模型失败，都显式关闭框架提供的上传文件对象。
- 应用不持久化原始文件；multipart 实现可以在请求期间使用框架管理的临时 spool，关闭后释放。
- 当前只接受 M2-B 已实现的 Markdown/TXT Allowlist 和 UTF-8/UTF-8 BOM。

multipart 解析使用 `python-multipart`，作为 FastAPI 文件上传所需的直接运行时依赖锁定。

### 4. 错误与状态响应

应用错误返回稳定的 `code`、可公开 `message` 和 `retryable`，不包含底层异常、连接串、模型
缓存路径或文档正文。不存在的知识库或文档返回 404；slug 冲突和版本状态冲突返回 409；
不支持或无效的文档返回 422；基础设施或本地模型暂时不可用返回 503。

FastAPI 对路径 UUID、缺少 multipart 字段和请求 Schema 的校验也转换为同一错误外壳，
使用 `request_validation_error` 且不回显不可信输入。

### 5. 组合与生命周期

默认应用在 FastAPI lifespan 打开数据库和 Redis 后构建一次入库服务图，共享懒加载的
Tokenizer、Embedding 模型和数据库连接池；关闭时仍由现有资源生命周期释放连接池。
测试可以注入类型化用例替身，不要求下载模型或连接真实基础设施。

## 备选方案

### 立即引入后台任务队列

可以快速返回 202 并支持进度查询，但需要任务持久化、幂等、重试、取消和 Worker 运维，超出
当前最小纵向范围，也属于新增核心基础设施。

### 使用 JSON Base64 上传

实现简单，但会增加传输体积并失去标准文件上传工具链，不适合作为文档 API 基线。

### 只提供文档端点，不提供知识库创建

端点更少，但全新环境没有公开方式获得合法知识库 ID，无法形成可复现纵向闭环。

### 软删除

可以保留审计历史，但当前表没有删除状态和检索过滤契约。M2-A 已接受作用域内的级联硬删除，
本阶段不修改核心表结构。

## 后果

- Markdown/TXT 可以从标准 HTTP 上传完整进入 pgvector，并通过公开状态接口验证。
- 同一 `source_key` 再次上传会建立新版本，数据库仍只允许一个 active 版本。
- 删除是不可恢复的级联硬删除；加入权限系统前，该 API 仅适合受控开发和演示环境。
- 当前同步 API 不提供后台进度、断点续传、对象存储、版本历史列表或失败重试。
- 新增端点属于公开契约；后续修改路径、字段、状态码或错误结构需要更新 ADR 或增加 API 版本。
